Is the WISE palette, type & spacing accessible?

This module does two things, live in your browser. First, it fetches and grades every shipping HTML page against a battery of automated WCAG checks, listing each page with a letter grade (see Page grades) — and it keeps re-checking so the grades stay current as pages change. Second, it audits every design token shipped in pages/wise.css against the Web Content Accessibility Guidelines — targeting Level AAA (SC 1.4.6 Contrast Enhanced: 7:1 for normal text, 4.5:1 for large). Color-contrast ratios are recomputed using the WCAG relative-luminance formula, so the verdicts can never drift from the actual hex values. Toggle the theme in Appearance to re-run the audit against the dark palette.

HTML pages reviewed & graded

Every shipping HTML page is fetched live and run through a set of automated WCAG checks (document language, page title, zoomable viewport, image alt text, accessible names on controls, labelled form fields, heading structure and landmarks). Each page gets a letter grade. This re-runs on load, on demand, when you return to the tab, and on a timer — so a page is re-graded shortly after it changes.

Typography scale

The UI is set in DM Sans. The base UI size is small (--fs-ui: 0.75rem = 12px), which is the single biggest accessibility risk in the system — see findings.

12px base is dense but fully zoomable to 200%

WCAG has no hard minimum font size. The 12px (--fs-ui) and 11px (--fs-label) labels stay legible because their text colors now carry AAA-level contrast (≥7:1, see findings 1–2), and the text-scale control (--wise-text-scale) plus browser zoom both reach 200% without clipping — satisfying SC 1.4.4.

Spacing & radius scale

Radii tokens drive every card, pill and module. Spacing is applied ad-hoc (4 / 8 / 12 / 14 / 18 / 28 / 32px) rather than via named tokens.

Generated audit of the WISE design tokens (pages/wise.css) plus a live, per-page WCAG review of every shipping HTML page in the project. Pages are fetched with cache: no-store on load, on demand, on tab focus and on a polling timer, then parsed and graded in the browser — so grades re-evaluate shortly after any page is updated. Contrast ratios use the WCAG 2.1 relative-luminance algorithm; translucent tokens (rgba borders, soft tints) are alpha-composited over their resolved background before measuring. This is an automated review and complements, but does not replace, testing with assistive technology and real users.
