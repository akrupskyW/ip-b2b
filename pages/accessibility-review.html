WCAG 2.1 AAA / 2.2 conformance audit

Is the WISE palette, type & spacing accessible?

This page does two things, live in your browser. First, it fetches and grades every shipping HTML page against a battery of automated WCAG checks, listing each page with a letter grade (see Page grades) — and it keeps re-checking so the grades stay current as pages change. Second, it audits every design token shipped in pages/agent-page.css against the Web Content Accessibility Guidelines — targeting Level AAA (SC 1.4.6 Contrast Enhanced: 7:1 for normal text, 4.5:1 for large). Color-contrast ratios are recomputed using the WCAG relative-luminance formula, so the verdicts can never drift from the actual hex values. Toggle the theme to re-run the audit against the dark palette.

SC 1.4.4 / 1.4.12

text_fieldsTypography scale

The UI is set in DM Sans. The base UI size is small (--fs-ui: 0.75rem = 12px), which is the single biggest accessibility risk in the system — see findings.

check_circle
12px base is dense but fully zoomable to 200%

WCAG has no hard minimum font size. The 12px (--fs-ui) and 11px (--fs-label) labels stay legible because their text colors now carry AAA-level contrast (≥7:1, see findings 1–2), and the text-scale control (--wise-text-scale) plus browser zoom both reach 200% without clipping — satisfying SC 1.4.4.

Generated audit of the WISE design tokens (pages/agent-page.css, pages/portfolio.css, pages/wiseai-chat.css) plus a live, per-page WCAG review of every shipping HTML page in the project. Pages are fetched with cache: no-store on load, on demand, on tab focus and on a polling timer, then parsed and graded in the browser — so grades re-evaluate shortly after any page is updated. Contrast ratios use the WCAG 2.1 relative-luminance algorithm; translucent tokens (rgba borders, soft tints) are alpha-composited over their resolved background before measuring. This is an automated review and complements, but does not replace, testing with assistive technology and real users.
